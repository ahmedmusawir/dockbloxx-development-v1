# Ticket 3 — Phase 1 Step 8: Adjacent findings — REPORT ONLY (GUARDRAILS 5/13). Nothing implemented.

Each item: evidence · impact · follow-up candidate. None block Ticket 3.

1. **`handlePoleStyleChange` is state-only.** `BloxxPricing.tsx` L399–401 (now ~L404) sets `selectedPoleStyle` and never touches `cartItem.variations`; the cart's `Pole Style` value comes only from the shape-driven sync effect (L84–94) and `normalizePoleStyle`. A shopper who picks `square_octagon` still ships `square`. Cosmetic today because the normalizer collapses it, but the order never records the real pick. **Follow-up:** Ticket "Pole Style cart write" — mirror `handleMaterialSelection` (filter-then-append) and decide whether the order should carry the key or a label.
2. **Duplicated init effects.** Two `useEffect(…, [variations])` blocks (L116–166 and L169–226, now +4/+10) do the same work; the second wins. A third effect (L236–253) repeats the shape→style switch a fourth time. Every future option must be seeded in both arrays (as Step 4 had to). **Follow-up:** collapse to one init effect + one `shapeToDefaultStyle()` helper; regression-test with the Step 7 suite.
3. **`makeKey` has a stray brace in three of four copies.** `useCartStore.ts` L93, L115, L133 build `…)}}::…` while `addOrUpdateCartItem` L63 builds `…)}::…`. Each function is self-consistent, so nothing breaks today, but `addOrUpdateCartItem` and `setOrReplaceCartItemQuantity` compute different keys for the same item. **Follow-up:** one exported `makeKey` used by all five call sites.
4. **Cart key is order-sensitive and `handleShapeSelection` reorders entries.** Key = `JSON.stringify(variations)`; the shape handler filters then appends, moving `Pole Shape`/`Pole Size` to the end. Same selections reached in a different click order can become two lines. Pre-existing; Pole Material adds one more movable entry. Also: carts persisted before this deploy lack `Pole Material`, so they will not merge with post-deploy adds. **Follow-up:** sort-by-name inside `makeKey` (with the fix above).
5. **Leftover `console.log` in production code.** `BloxxPricingPoleStyles.tsx` L66 logs every style click. **Follow-up:** remove during the Pole Style ticket.
6. **`src/lib/test.ts` is a bare sanity test living under `src/`.** Jest counts it as a suite (15th). **Follow-up:** delete or move to `tests/`.
7. **Thank-you page variations line is commented out.** `ThankyouPageContent.tsx` L137–140. Shoppers see no option summary on confirmation. **Follow-up:** product decision — restore (generic, would show `Wood`) or delete the dead block.
8. **Cart strips print values only, so `Pole Style` shows as lowercase `square` next to `Square`.** Generic renderers at CartSlide L122–125 etc. Director accepted as-is for Pole Material. **Follow-up:** bundle with the Pole Style ticket if a label is ever stored.
9. **Round products offer only size `Other`, and Add to Cart hard-aborts via `alert()`.** `ProductDetails.tsx` L100–106. Observed during Step 4 verification. Working as designed, but the `alert()` is untestable in e2e without dialog handling and unfriendly on mobile. **Follow-up:** inline validation message instead of `alert`.
10. **DoD example slug does not exist on staging.** `giraffe-g20-pressure-washer-mount-only` is absent from the 47 published products. Already routed: TEST BUY uses `whos-your-caddie`. **Follow-up:** confirm whether Giraffe G20 is production-only or renamed, for the client report.
