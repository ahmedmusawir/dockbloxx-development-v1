## Lessons Learned

- **"Diff before save" checkpoint works.** Tony's instruction to show the exact diff before invoking `Edit` gave him a bytes-level review checkpoint without needing to re-read the file afterwards. Cost: one extra CLI turn per edit. Value: caught nothing this session, but the discipline is worth it for tracking/analytics changes where a missed subtlety costs real revenue metrics downstream. Repeat this pattern for future single-file targeted edits.
- **"Verbatim" for docs = words verbatim, minimum enclosing formatting preserved.** When applying `CLAUDE_MD_PATCH.md` to the pack CLAUDE.md, strict literal verbatim (no markdown) would have broken the doc's bold-label + backtick-identifier style. Correct interpretation: preserve words 1:1, keep the doc's local formatting conventions (`**bold labels**`, `` `code identifiers` ``) intact. Flagged the two stylistic decisions to Tony; he didn't push back — confirming the read.
- **Track A / Track B ownership split is a first-class pattern.** Some tickets split between "app fix in the repo" and "config/container fix outside the repo." Claude's scope is strictly the in-repo half; GUARDRAIL 10 forbids writing "compensating code" for the outside-repo half. Ticket doesn't close until BOTH halves are done AND validation ties them together. This pattern needs to be surfaced explicitly in the manager doc (was clarified in v1.1's patch — noteworthy for future App Factory pack templates).
- **A React `useRef` guard is NEVER a persistent guard.** Component-scoped state, discarded on unmount. Any time you see `useRef(false)` used as a "fire only once" flag, ask: fire once per WHAT boundary? If it needs to be per-order or per-session, `useRef` is the wrong tool. This showed up TWICE in the same file this session (A1 fixed `hasTrackedPurchase`; A3 report-only flagged `isCustomerRegistered` for the same pattern). Watch for this in other flows.
- **Verify pre-state, not just post-state.** Carryover lesson from 2026-06-11 session was applicable here: before proposing A2, I confirmed A1's landing state in the file rather than relying on memory. Same discipline prevented mis-plans against a stale mental model.
